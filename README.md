# 巡检规则阈值评估 · 人工复核协作台

用本地造数跑通的完整流程：模型只产出规则分数 → 阈值标记进入人工复核 →
复核台账（含未查到设备留存）→ 补判漏报并区分适用范围 → 阈值搜索给出
「优先减少漏报」与「节约复核工时」两套可比较结果。仅依赖 Node.js 内置模块。

## 启动

```bash
node server.js          # 默认端口 3000
PORT=8080 node server.js # 端口读 process.env.PORT，绑定 127.0.0.1
```

打开 http://127.0.0.1:3000 ，页面上可操作：

1. **运行原阈值评估**：按原阈值（造数中为 60，全局范围）评估并留存快照，重复运行只追加；
2. **补判一条漏报**：候选仅限「已查到、原阈值未标记、尚无标签」的记录，
   补判时区分 `global / region / type / record` 适用范围，补判后按该范围重算，
   旧阈值评估快照原样保留；
3. **查看成本权衡**：阈值网格（30/40/50/60/70/80/90）全量结果 + 两套策略
   （减漏报、省工时）+ 仅按准确率的对照项，避免只挑准确率高的方案。

业务结果区各卡片均带 `data-evidence-result` 属性（如 `latest-evaluation`、
`tradeoff`、`evaluation-history`、`adjudication-ledger`、`record-details` 等），
可直接核对操作前后内容变化；最外层容器为 `data-evidence-result="business-results"`。

## 关键业务约定

- **模型只用规则分数模拟**：`score >= threshold` 即标记复核，没有任何模型化判定。
- **复核子集不代表全部**：准确率/召回率/漏报率等只在已复核子集上计算，
  每份评估快照都带覆盖说明（caveats）；已查到但未复核的记录标为 `unlabeled`，不进指标分母。
- **未查到设备**：`found=false` 的记录留存到 `missing` 列表，不参与混淆矩阵与工时估算。
- **补判适用范围**：全局补判在所有评估中生效；区域/类型/单记录补判只在同范围
  评估中采信，全局评估不采信，避免局部结论污染全局口径。
- **省工时策略的约束**：漏报数不得超过「原阈值漏报 + 容忍条数」（造数配置为 +1）；
  无可行解时回退原阈值并标记 `feasible=false`，不会悄悄放宽约束。
- 工时 = 标记复核条数 × 单条复核工时（造数为 15 分钟/条）。

## 测试

```bash
node --test
```

覆盖正常结果（混淆矩阵、未查到设备留存、未复核记录、阈值网格单调性、
两套策略差异、范围采信、快照留痕、HTTP 全流程）与异常结果（重复补判、
非漏报补判、未查到设备补判、记录不存在、坏 JSON、未知接口、缺范围参数等）。
HTTP 用例会在子进程中以 `PORT=4317` 启动真实服务验证。

## 目录结构

```
server.js              HTTP 服务（内置 http，绑定 127.0.0.1，读 PORT）
store-factory.js       状态仓库工厂
lib/engine.js          纯函数领域引擎（评估、阈值搜索、策略选择、补判校验）
lib/store.js           内存状态：评估快照 append-only、补判台账、成本权衡
lib/data.js            本地确定性造数（20 条记录/14 条复核/5 条未复核/1 条未查到）
lib/errors.js          ValidationError（统一映射 HTTP 400）
public/                无框架前端（index.html / app.js / styles.css）
test/                  node --test 用例
```
